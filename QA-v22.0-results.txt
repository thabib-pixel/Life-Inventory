LOADING / DATA SAFETY CHANGES
- Version-specific IndexedDB namespace: LifeTrackerInventory_v22_0 / latest-v22.0.
- Previously saved versions cannot overwrite the new v22 baseline.
- The initial inventory renders immediately after external JSON parsing. The app no longer writes a full ~74 MB baseline into IndexedDB before showing the cards. Edits still trigger persistent saves.

LIMITATIONS
- The Chromium browser cannot navigate to a local web server in this environment (net::ERR_BLOCKED_BY_ADMINISTRATOR).
- Browser interactions used page.set_content with an image-light copy of the exact same inventory records and simulated IndexedDB; real origin-backed IndexedDB and GitHub Pages production deployment were NOT verified.
- A first load must still download and parse the ~74 MB inventory JSON, so visible delay remains possible on some connections/devices.
- No claim is made that every conceivable production behavior has been tested.
